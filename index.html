Real-time POS streaming

Kafka → Snowpark → Snowflake Streams/Tasks → data marts

Problem

Point-of-sale data arrived through point-to-point integration flows that were brittle under peak load and hard to replay, so reporting lagged and recoveries meant manual backfills.

Architecture

Key decisions

  • Kafka as the system of record for events, so consumers can replay from offsets instead of re-requesting data from stores.
  • Land raw payloads as VARIANT first, then parse with Snowpark — schema changes don't break ingestion.
  • Streams & Tasks for incremental, CDC-style merges into curated tables; dbt owns the mart layer.
  • Error monitors with automatic reprocessing of failed micro-batches.

Outcome

Near-real-time sales visibility on a pipeline that recovers on its own, replaces fragile integrations, and gives downstream teams a single trusted feed.

Catching a silent vendor data rewrite

Detecting retroactive changes in third-party history

Problem

A third-party source quietly restated historical records. Loads still succeeded and row counts looked normal, but trends shifted under analysts' feet with no change notice.

Architecture

Key decisions

  • Keep every vendor delivery as an immutable, append-only snapshot, so history can always be compared and rolled back.
  • Hash closed historical periods on every load; any fingerprint change in a "closed" window is a restatement.
  • Data-quality tests on distributions, not just nulls and counts, gate promotion to curated tables.
  • Quarantine suspect loads and alert owners instead of silently overwriting.

Outcome

Restatements surface as explicit, reviewable events instead of mystery trend shifts, and the vendor contract now has a technical enforcement point.

Agentic API orchestrator

LangGraph stateful agent + vector search over API metadata

Problem

Finding the right internal API — endpoint, scope, contract — meant digging through repositories and asking around. Calling it correctly took even more context.

Architecture

Key decisions

  • An indexing pipeline extracts endpoints, scopes, and contracts from repositories into a central registry, so retrieval stays current without manual docs.
  • LangGraph for explicit state and branching: retrieve → confirm → gather params → execute → explain.
  • The execute agent asks targeted follow-up questions for missing payload fields rather than guessing.
  • Raw API responses are summarized into plain language, with the underlying call shown for transparency.

Outcome

People describe what they need in plain English and get the right API — and often the answer itself — without knowing where it lives or how to call it.
